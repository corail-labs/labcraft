LabCraft 0.4.0, the editor: a graphical dataflow language, which you now draw. The diagram that 0.3.0 showed
read-only is an editor, on the desktop and in the browser, and an AI agent attached to the window edits the same
program as you, in one history. It is the first release for people outside the project: instruments are still
simulated, and the installer is not signed yet.

## What is in it

**The diagram editor** (`labcraft`, on Windows, Linux and macOS):

- Draw a function with the mouse and the keys: quick insertion of a node by its name, wires drawn from terminal to
  terminal, with branches, and a wire routed by hand; select, move, copy, paste, duplicate and delete; a drag drops
  nodes into another frame.
- Structures: surround a selection with a `match`, a `for` or a `loop`; resize them; choose what a value leaving a loop
  gives: the list of its values (`collect`), or its value at the last iteration (`last`, new in the language).
- The signature of a function, its terminals and its block; new functions and types, renamed everywhere they are used;
  *Make a function…* from a selection.
- One history for everything that changes a file: Ctrl+Z undoes your step, a step of the agent, or a write made by
  another program, and gives back the file byte for byte. The file is the truth: closing and opening the project gives
  the same drawing, and moving a node changes one line of its `layout` section.
- The `Text` panel edits the same function as text, with its diagnostics, hover, completion and *Go to definition*.
- The `Block` view of a function or a library, the primitives of `core` drawn as blocks, wires coloured by their type,
  a light and a dark theme, and the *Settings* dialog; a double click on a call opens the function it calls.
- Function tabs can be detached into windows of their own, and the start page opens recent projects.

**The AI agent attached to the IDE.** `labcraft-cli mcp`, started by an agent in the folder of a project open in the
window, attaches to that window: the agent edits through the same commands as you, under a policy you choose at its
first connection (*Ask*, *Edits* or *All*), and waits while you are in the middle of a gesture. The window shows what it
touched, with *Show* and *Undo*, and one switch turns AI off. *Help > Connect an AI agent* (or `labcraft-cli mcp setup`)
writes the configuration of the MCP clients it finds.

**The web page** is the same window, in the browser: it opens the examples, or a folder dropped on it, as a project in
memory, edits it, and *Download* saves the project as a zip.

**The command line.** `labcraft-cli exec` runs one editing command from a terminal or a script; `labcraft FILE` opens a
file with its project; `check` and `diagram` read the new `block`, `terminals`, `outline` and `[mask]` sections.

**On Windows**, an MSI installer, and a double click on a `.lcf` or a `.lct` file opens it in LabCraft.

**A new logo**, on the executables, the window and its top bar, the MSI and the web page.

**Early pieces of 0.5.0**, the first real bench, are in the binaries but not released yet; they may still change:
integers in hexadecimal and binary, bitwise operations, `quotient` and `remainder`; the `bytes` type; the libraries
`net` (TCP and UDP) and `serial`, with their simulators; more `scpi` queries; the example `modbus_tcp`, a protocol
written in LabCraft; and `--allow-hardware` and `--allow-path`, without which a run reaches no real endpoint and no
file outside its project.

**Changes from 0.3.0.** `scpi.query_f64` gives the session first among its outputs, then the value
(`dmm2, raw, e2 = scpi.query_f64(dmm, "MEAS:VOLT:DC?")`); a program that takes them in the old order no longer checks,
and `check` says where. Some diagrams are drawn
differently: wires between neighbours are straight, and each frame has its own grid of 8.

The acceptance scenarios that 0.4.0 passes, the one figure it misses (the new drawing after a drop of 100 nodes, in
about 400 ms of 300 proposed, #376) and the one step that has no gesture yet (the unit of `with_unit`, #378), are in
[docs/acceptance-m1.md](https://github.com/corail-labs/labcraft/blob/v0.4.0/docs/acceptance-m1.md).

## The archives

| File | For |
|---|---|
| `labcraft-0.4.0-windows-x64.msi` | Windows 10 and 11, x64: the installer (below) |
| `labcraft-windows-x64.msi` | The same installer, under a name that does not change with the version |
| `labcraft-0.4.0-windows-x64.zip` | Windows 10 and 11, x64, without an install |
| `labcraft-0.4.0-linux-x64.tar.gz` | Linux x64, glibc 2.35 or later (Ubuntu 22.04, Debian 12, Fedora 36 and later) |
| `labcraft-0.4.0-macos-arm64.tar.gz` | macOS on Apple Silicon |
| `labcraft-0.4.0-macos-x64.tar.gz` | macOS on Intel |
| `labcraft-web-0.4.0.zip` | The web page, a folder to serve |
| `SHA256SUMS` | The SHA-256 of each file |

Each archive holds `labcraft-cli`, `labcraft`, the example programs in `examples/`, the simulated instruments of the
`visa` library in `sim/`, this note, the licences and the attributions, and in `THIRD-PARTY-LICENSES.txt` the
licences of the Rust crates built into the binaries.

## Try it

In a terminal, in the folder of the archive (on Windows, in PowerShell; after the MSI, in any folder, without `./`):

```sh
./labcraft-cli check examples
./labcraft-cli run --sim sim/dmm-230V.toml --arg resource=SIM::DMM0 examples check_voltage
./labcraft examples
```

`run` prints the outputs of `check_voltage` against a simulated multimeter. In the window, open `check_voltage`,
change a limit or add a node, and run it again from the `Run` panel. To attach an AI agent, use *Help > Connect an AI
agent*, or, here in Claude Code, from the folder of the project:

```sh
claude mcp add labcraft -- labcraft-cli mcp --project .
```

On macOS, the system refuses a downloaded binary that is not notarized: remove the quarantine once, in the folder of
the archive, with `xattr -d com.apple.quarantine labcraft labcraft-cli`. On Linux, the window needs a Vulkan or OpenGL
driver, and X11 or Wayland; the command line needs neither.

**The web page** runs from a web server, not from a file opened in the browser. In its folder, for example:
`python3 -m http.server 8000` (`py -m http.server 8000` on Windows), then open `http://localhost:8000/`.

## Install on Windows

`labcraft-0.4.0-windows-x64.msi` (the same file as `labcraft-windows-x64.msi`) installs LabCraft for every user of the machine, in `C:\Program Files\LabCraft`:
the IDE `labcraft` in the Start menu, and `labcraft-cli` in the `PATH`, so that a terminal opened after the install,
or an AI agent started after it, finds it by its name; a terminal open during the install keeps its old `PATH`. A double
click on a `.lcf` or a `.lct` file opens it in LabCraft, with its project; Win+R `labcraft` starts the IDE. It holds the same files as the zip archive. A later version installed over it
replaces it; *Settings > Apps > Installed apps* removes it.

**The installer is not signed yet.** Windows says so twice:

- When it opens, SmartScreen may show "Windows protected your PC": choose *More info*, then *Run anyway*.
- Windows then asks to allow an app from an unknown publisher to make changes to the device: choose *Yes*. Installing
  for every user needs an administrator.

The zip archive needs no install: unzip it anywhere, and run the programs from its folder. SmartScreen may stop its
first launch too; in `cmd.exe`, type `labcraft-cli` without `./`.
